# assets/

Optional real photography for SMIVAI. The app works with none of these —
every illustration ships inside the code as SVG — but a photograph placed
here takes over the slot it belongs to.

## welcome.jpg

Shown in place of the drawn scene on the welcome screen.

| | |
|---|---|
| **File name** | `welcome.jpg` (exactly this — nothing else is looked for) |
| **Shape** | landscape, 5:3; the frame crops to that ratio, centred slightly above the middle |
| **Size** | about 1200 x 720, under ~300 KB so the first screen stays fast |
| **Subject** | the people SMIVAI is for — older adults, North-East Indian, using the app on a phone or tablet |

Drop the file in and reload; remove it and the drawn scene comes back. No
code change either way.

**Currently installed:** an AI-generated photograph of an older couple on a
bamboo verandah in a hill village, looking at a tablet together. It was
generated by the project owner in an external image tool and fitted here
to 1200 x 720 / 161 KB. Nobody in it is a real, identifiable person, so no
model release applies — but the image is also not documentary, and should
not be captioned as a real SMIVAI user.

When you swap the file, update the alt text with it: `wl_photo_alt` in
`js/screens/landing.js` describes what the picture shows, and a screen
reader will otherwise announce the old scene.

## login-patient.jpg / login-caregiver.jpg / login-doctor.jpg

Shown in the side panel of the sign-in screen, one per role, in place of
that role's drawn figure.

| | |
|---|---|
| **File names** | `login-patient.jpg`, `login-caregiver.jpg`, `login-doctor.jpg` |
| **Shape** | square, 1:1 |
| **Size** | about 800 x 800, under ~200 KB |
| **Subject** | someone that role will recognise as themselves |

Each is independent: a role with no file keeps its drawing. The panel is
hidden on phones, where the form takes the whole screen.

**Currently installed:** `login-patient.jpg` only — a square crop of the
same AI-generated verandah scene as the welcome picture, framed on the
couple and their tablet. Caregiver and doctor still show their drawings.

Alt text for these lives in `js/screens/login.js` (`lg_alt_patient`,
`lg_alt_caregiver`, `lg_alt_doctor`) — update it when you change a photo.

## patient-hero.jpg

Shown in the patient dashboard hero, beside "Good morning, <name> Ji!",
in place of the drawn elder.

| | |
|---|---|
| **File name** | `patient-hero.jpg` |
| **Shape** | landscape, 4:3 |
| **Size** | about 1000 x 750, under ~200 KB |
| **Subject** | a scene the patient would recognise as their own day |

One thing this slot gives up: the drawn figure is generated per patient
(their gender, dress and district feed into it), so every patient sees
someone a little like themselves. A photograph is the same for everyone —
a house picture rather than a portrait of the person signed in. Remove
the file and the personalised drawing returns.

### One per gender

The hero looks for `patient-hero-male.jpg` or `patient-hero-female.jpg`
first, by the patient's own gender, and falls back to `patient-hero.jpg`
for anyone whose gender is not one of those two. Same rule as the
avatars, same reason: a woman signing in should not be greeted by a
picture of a man.

**Currently installed:** all three. `-male` is an older man on a bamboo
verandah reading a tablet; `-female` is the same verandah framed on an
older woman; the plain one shows the couple, so it suits anybody. A
single figure suits this slot, because the hero greets one person by
name.

Alt text: `hero_photo_alt` in `js/screens/patient.js`.

## avatar-male.jpg / avatar-female.jpg

The passport-style headshot used for the signed-in person's own avatar —
the profile chip in the top bar, and the large avatar on their profile
page. Picked by that person's `gender`.

| | |
|---|---|
| **File names** | `avatar-male.jpg`, `avatar-female.jpg` |
| **Shape** | square, 1:1 — head and shoulders, face centred, like a passport photo |
| **Size** | about 320 x 320, under ~50 KB |

### Caregivers and doctors

They use their own files, never the patients' — a doctor wearing a
patient's face would be worse than no photograph at all. Each looks for
its gender first, then a general one for the role, and falls back to
initials:

| Who | Looked for, in order |
|---|---|
| caregiver | `avatar-caregiver-<gender>.jpg`, `avatar-caregiver.jpg` |
| doctor | `avatar-doctor-<gender>.jpg`, `avatar-doctor.jpg` |
| patient | `avatar-<gender>.jpg` |

Same square 1:1 headshot, about 320 x 320. A caregiver reads as a
younger adult; a doctor wears a coat or scrubs. The demo's caregivers
are Nabanita Sharma (female) and Pranjal Gogoi (male), and its doctor,
A. Choudhury, is male.

**Currently installed:** all four — `avatar-caregiver-female`,
`avatar-caregiver-male`, `avatar-doctor-female`, `avatar-doctor-male`,
AI-generated on a plain grey backdrop to match the patients' pair.

The same faces appear in two more places, both of which show one person
at a time: the three role cards on the welcome screen ("I am a
Patient / Caregiver / Doctor"), and the sign-in side panel, which reads
`login-patient.jpg`, `login-caregiver.jpg` and `login-doctor.jpg`.

### Everyone else uses the same files

Every avatar in the app — the doctors in an appointment row or the
"Choose a doctor" list, the patients in a caregiver's or doctor's list —
now resolves through the same rule, by the id the app already holds:

    ids starting dr_ or dir_  ->  doctor
    ids starting cg_          ->  caregiver
    ids starting pat_         ->  patient

Family and emergency contacts are left alone: there is no photograph
that honestly stands for somebody's daughter, so they keep their drawn
bust.

**The catch: one photograph per gender means repeated faces.** Four male
doctors in the directory share one face. It reads fine in a single row
and poorly in a long list, so give the people who matter their own
picture:

```js
// js/ui/components.js, or anywhere after it loads
S.Photo.PEOPLE['dir_neha'] = 'assets/doctor-dir_neha.jpg';
S.Photo.PEOPLE['pat_ramesh_das'] = 'assets/patient-ramesh.jpg';
```

A person listed there wins over the gender file. Same square 1:1
headshot, about 320 x 320.

**Currently installed:** both, cropped from the AI-generated verandah
photographs.

## Before you publish a photograph of real people

The app is a health product, so a photograph here reads as "these people
use SMIVAI".

- Get a **model release** from everyone recognisable in the frame. A stock
  licence covers the photographer's copyright; it does not, on its own,
  give you the right to imply that the people in it endorse a health
  service. Unsplash and Pexels both say this explicitly.
- Keep the licence or release on file with the image.
- If you cannot obtain a release, keep the drawn scene: it represents the
  same people without putting anyone's face to a claim they never made.
